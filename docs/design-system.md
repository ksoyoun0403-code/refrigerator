# mydish 디자인 시스템 v0.1

이 문서는 `mydish` 전 화면에 공통 적용할 최소 디자인 기준을 정의한다. 참고 디자인의 따뜻한 포인트 컬러, 둥근 형태, 평면적인 카드, 분명한 선택 상태를 차용하되 브랜드나 화면 구성을 그대로 복제하지 않는다.

현재 단계에서는 앱 아이콘, 로고, 일러스트레이션, 개별 화면의 완성 시안은 다루지 않는다. 기능 구현 중 반복 사용되는 토큰과 기본 컴포넌트만 범위에 포함한다.

## 1. 디자인 원칙

1. **정보가 먼저 보인다.** 재료명과 유통기한이 장식보다 우선한다.
2. **오렌지로 브랜드를 기억하게 한다.** 주요 행동, 활성 상태, 핵심 브랜드 표현에 일관되게 오렌지를 사용한다.
3. **상태색에는 역할을 부여한다.** 그린은 성공, 레드는 오류와 만료처럼 의미가 있는 상태에만 사용한다.
4. **선택과 실행을 구분한다.** 선택 상태는 배경과 테두리로, 실행 버튼은 채워진 색상으로 표현한다.
5. **기본 화면은 평면적으로 유지한다.** 카드마다 그림자를 넣지 않고 테두리와 배경 차이로 계층을 만든다.
6. **한 손 사용을 고려한다.** 누를 수 있는 영역은 최소 44px을 확보한다.

## 2. 색상

색상은 화면에서 직접 16진수 값을 쓰지 않고 아래 의미 기반 이름으로 사용한다.

### 브랜드와 표면

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `color.brand.primary` | `#F97316` | 브랜드 표현, 활성 아이콘, 핵심 선택 상태 |
| `color.brand.action` | `#C2410C` | 흰 글자가 올라가는 주요 버튼 |
| `color.brand.pressed` | `#9A3412` | 주요 버튼을 누른 상태 |
| `color.brand.soft` | `#FFF0E6` | 선택 배경, 보조 강조 영역 |
| `color.brand.onPrimary` | `#2B1B15` | 밝은 대표 오렌지 위의 텍스트와 아이콘 |
| `color.canvas` | `#FFF9F3` | 앱 기본 배경 |
| `color.surface` | `#FFFFFF` | 카드, 입력창, 하단 작업 영역 |
| `color.surface.muted` | `#F8F4F1` | 비활성 영역, 구분된 보조 영역 |
| `color.border` | `#E9DED7` | 기본 테두리와 구분선 |
| `color.border.strong` | `#CDBBAF` | 포커스되지 않은 강조 테두리 |

### 텍스트와 상태

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `color.text.primary` | `#2B1B15` | 제목, 재료명, 주요 정보 |
| `color.text.secondary` | `#5F4B43` | 본문, 설명 |
| `color.text.muted` | `#81736D` | 보조 문구, 힌트, 비활성 텍스트 |
| `color.success` | `#2F6B45` | 저장 완료, 연결 성공 |
| `color.success.soft` | `#EAF3EC` | 성공 상태의 배경 |
| `color.warning.ink` | `#7A5700` | 확인이 필요한 정보의 텍스트 |
| `color.warning.soft` | `#FFF8DF` | 확인이 필요한 정보의 배경 |
| `color.danger` | `#B42318` | 삭제, 오류, 만료 상태 |
| `color.danger.soft` | `#FEE4E2` | 오류와 만료 상태의 배경 |

대표 오렌지 `brand.primary` 위에는 `brand.onPrimary`를 사용한다. 흰색 글자가 필요한 주요 실행 버튼은 더 짙은 `brand.action`을 사용한다. 이 구분으로 오렌지를 주색으로 유지하면서 작은 글자의 명암 대비도 확보한다.

유통기한 상태는 공통 의미를 유지한다.

- 일반: 기본 표면과 텍스트
- 임박: `brand.soft` 배경과 `brand.action` 텍스트
- 만료 또는 삭제: `danger.soft` 배경과 `danger` 텍스트
- 확인 필요: `warning.soft` 배경과 `warning.ink` 텍스트

## 3. 타이포그래피

한글 가독성과 유지보수를 위해 글꼴 체계는 하나만 사용한다. 현재는 iOS와 Android의 시스템 산세리프를 사용하고, 브랜드 디자인 적용 시 `Pretendard`로 일괄 교체한다. 글꼴 파일을 도입하기 전에는 새로운 폰트 Library를 추가하지 않는다.

| 토큰 | 크기 / 줄높이 | 굵기 | 용도 |
| --- | --- | --- | --- |
| `type.display` | 34 / 43 | 800 | 홈의 핵심 숫자나 짧은 메시지 |
| `type.heading1` | 28 / 36 | 800 | 화면 제목 |
| `type.heading2` | 20 / 28 | 800 | 영역 제목 |
| `type.title` | 18 / 25 | 700 | 카드 제목, 주요 입력값 |
| `type.body` | 16 / 24 | 400 | 기본 본문과 입력값 |
| `type.bodyStrong` | 16 / 24 | 700 | 강조 본문 |
| `type.label` | 14 / 20 | 700 | 필드명, 배지, 보조 버튼 |
| `type.caption` | 13 / 19 | 400 | 설명, 날짜 보조 정보 |
| `type.button` | 16 / 20 | 800 | 주요 버튼 |

- 제목에는 순수 검정 대신 `text.primary`를 사용한다.
- 카드 안의 재료명은 최대 두 줄, 유통기한은 한 줄을 기본으로 한다.
- 숫자와 날짜는 같은 화면에서 동일한 형식을 유지한다.

## 4. 간격과 레이아웃

모든 간격은 4px 단위로 맞춘다.

| 토큰 | 값 | 대표 용도 |
| --- | --- | --- |
| `space.1` | 4 | 아이콘과 짧은 라벨 사이 |
| `space.2` | 8 | 밀접한 정보 사이 |
| `space.3` | 12 | 카드 내부 요소, 그리드 간격 |
| `space.4` | 16 | 기본 컴포넌트 안쪽 여백 |
| `space.5` | 20 | 넓은 카드 안쪽 여백 |
| `space.6` | 24 | 화면 좌우 여백, 영역 사이 |
| `space.8` | 32 | 큰 영역 사이 |
| `space.10` | 40 | 화면 상단 여백 |
| `space.12` | 48 | 큰 콘텐츠 구분 |

공통 레이아웃 기준은 다음과 같다.

- 화면 좌우 여백: 24px
- 재료 카드 그리드 간격: 12px
- 기본 영역 간격: 24px
- 큰 화면 구획 간격: 32px
- 하단 고정 작업 영역은 기기의 safe area를 포함한다.
- 재료 목록은 휴대폰 기준 2열을 기본으로 하되, 매우 좁은 화면에서는 각 카드의 읽기 가능 폭을 우선한다.

## 5. 모서리, 테두리, 그림자

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `radius.small` | 8 | 작은 배지, 칩 |
| `radius.medium` | 12 | 입력창, 보조 버튼 |
| `radius.large` | 16 | 재료 카드, 배너 |
| `radius.xlarge` | 24 | 이미지 미리보기, 큰 패널 |
| `radius.full` | 999 | 주요 CTA, 원형 버튼 |

- 일반 테두리는 1px, 선택 및 포커스 테두리는 2px을 사용한다.
- 기본 카드는 그림자를 사용하지 않는다.
- 화면 위에 떠 있는 하단 작업 영역, 모달, 팝오버에만 한 단계의 부드러운 그림자를 허용한다.
- 선택을 그림자만으로 표현하지 않는다.

## 6. 상호작용 상태

모든 누를 수 있는 컴포넌트는 다음 상태를 제공한다.

| 상태 | 표현 기준 |
| --- | --- |
| 기본 | 역할에 맞는 기본 배경, 테두리, 텍스트 |
| 눌림 | 배경색을 한 단계 진하게 하거나 불투명도 `0.82` 적용 |
| 선택 | `brand.soft` 배경과 2px `brand.primary` 테두리 |
| 비활성 | 동작 차단, 불투명도 `0.45`, 안내가 필요하면 이유 표시 |
| 로딩 | 중복 동작 차단, 버튼 문구 유지 또는 진행 표시 |
| 포커스 | 2px `brand.primary` 테두리 |
| 오류 | `danger` 테두리와 바로 아래 해결 가능한 안내 문구 |

색상만으로 상태를 구분하지 않는다. 선택 표시, 아이콘, 문구 또는 테두리 중 하나를 함께 사용한다.

## 7. 공통 컴포넌트

현재 기능에 필요한 공통 컴포넌트만 먼저 만든다.

### `Screen`

- 기본 배경, 좌우 여백, safe area를 통일한다.
- 스크롤 화면과 고정 화면 두 형태만 제공한다.

### `AppText`

- 타이포그래피 토큰과 텍스트 색상을 연결한다.
- 화면별 임의 크기와 굵기 사용을 줄인다.

### `Button`

- `primary`: 저장, 등록, 촬영처럼 화면의 대표 동작. `brand.action` 배경과 흰색 텍스트 사용
- `secondary`: 취소, 다시 선택처럼 되돌릴 수 있는 보조 동작
- `danger`: 삭제 확정
- `ghost`: 툴바의 편집, 삭제 진입처럼 가벼운 동작
- 기본 높이 48px, 작은 버튼 44px, 주요 하단 CTA는 필요할 때 56px을 사용한다.
- 주요 CTA는 `radius.full`, 관리용 작은 버튼은 `radius.medium`을 사용한다.

### `Card`

- 흰색 표면, 1px 기본 테두리, `radius.large`를 사용한다.
- 재료 카드의 핵심 정보는 재료명과 유통기한으로 제한한다.
- 편집 모드의 선택 카드는 `brand.soft` 배경과 `brand.primary` 테두리를 사용한다.
- 삭제 모드의 X 버튼은 최소 44px 터치 영역을 확보한다.

### `TextField`

- 기본 높이 48px 이상, `radius.medium`을 사용한다.
- 라벨, 입력값, 오류 문구의 위치를 모든 폼에서 통일한다.
- placeholder만으로 필드 의미를 전달하지 않는다.

### `Chip`과 `SegmentedControl`

- 적은 수의 단위 선택, 필터, 모드 전환에 사용한다.
- 선택 상태는 채워진 배경과 굵은 텍스트를 함께 사용한다.
- 화면 이동을 대신하는 탭과 일회성 필터를 같은 모양으로 혼용하지 않는다.

### `StatusBanner`

- 이미지 인식 실패, 날짜 확인 필요, 네트워크 오류처럼 사용자의 조치가 필요한 상태에 사용한다.
- 상태 색상, 짧은 설명, 가능한 경우 재시도 또는 수정 동작을 함께 제공한다.

### `SelectionActionBar`

- 편집 모드에서 선택한 재료를 반대 영역으로 이동하거나 취소할 때 사용한다.
- 하단 고정 영역으로 표시하며 버튼 순서는 `취소`가 왼쪽, 실행 동작이 오른쪽이다.
- 실행 문구는 대상에 따라 `일반 냉장고로 이동`, `사용 임박으로 이동`처럼 결과를 직접 설명한다.

## 8. 아이콘과 이미지의 임시 기준

정식 아이콘과 로고를 만들기 전까지 다음 기준만 지킨다.

- 한 화면에서는 같은 아이콘 계열과 선 굵기를 사용한다.
- 기능을 나타내는 아이콘에는 접근성 라벨을 제공한다.
- 아이콘만 있는 버튼도 최소 44px 터치 영역을 갖는다.
- 식품 이미지는 원본 비율을 유지하고 `cover`로 자르며, 비어 있을 때는 중립 표면을 사용한다.
- 로고, 앱 아이콘, 캐릭터, 장식용 일러스트의 스타일은 기능 흐름이 안정된 뒤 별도로 정의한다.

## 9. 적용 순서

1. 색상, 타이포그래피, 간격, 모서리 토큰을 `front/src/design-system/tokens.ts`에 정의한다.
2. `AppText`, `Button`, `Card`, `TextField`를 우선 공통화한다.
3. 냉장고 목록 화면에 `Card`와 `SelectionActionBar`를 적용한다.
4. 이미지 등록 화면에 `Button`, `TextField`, `StatusBanner`를 적용한다.
5. 화면 전환 후 시각 회귀와 iOS/Android 터치 영역을 확인한다.

초기 적용에는 외부 UI Library가 필요하지 않다. 기존 React Native `StyleSheet`와 작은 공통 컴포넌트로 구현하고, 정식 폰트나 아이콘 자산을 확정할 때만 의존성 추가를 검토한다.

## 10. 이번 버전에서 제외하는 항목

- 앱 아이콘과 로고
- 브랜드 일러스트레이션과 캐릭터
- 화면별 고정 시안과 세부 카피
- 다크 모드
- 복잡한 모션과 전환 효과
- 태블릿 전용 레이아웃

이 항목들은 핵심 등록·목록·편집 흐름이 안정된 뒤 확장한다.
