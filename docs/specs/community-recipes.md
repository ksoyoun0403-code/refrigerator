# 커뮤니티 레시피 요구사항

- 작성일: 2026-08-24
- 상태: 요구사항 확정
- 구현 상태: 사용자·인증, 냉장고 분리, 레시피 공유, 커뮤니티 검색·상세·북마크·댓글과 나의 요리책 구현 완료

## 1. 목적

사용자가 AI로 생성한 레시피를 커뮤니티에 공유하고, 다른 사용자가 레시피 이름이나 재료로 검색하여 상세 내용을 확인하고 북마크할 수 있게 합니다.

좋아요와 팔로우 기능은 포함하지 않습니다. 커뮤니티의 사용자 반응은 북마크, 공개 북마크 횟수와 댓글로 표현합니다.

## 2. 앱 진입과 사용자 정보

앱을 처음 사용하는 사용자는 회원가입 화면에서 다음 정보를 입력합니다.

- 아이디
- 비밀번호
- 닉네임

아이디와 닉네임은 각각 중복을 허용하지 않습니다. 기존 사용자는 아이디와 비밀번호로 로그인합니다.

이메일과 전화번호는 수집하지 않으며 계정 찾기 기능을 제공하지 않습니다. 회원가입 화면에서 아이디와 비밀번호를 잊으면 복구할 수 없음을 안내하고 비밀번호를 두 번 입력해 확인합니다. 로그인 화면은 사용자가 선택한 경우에만 아이디를 기기의 보안 저장소에 보관하며 비밀번호는 저장하지 않습니다.

로그인 상태에서는 현재 비밀번호를 확인한 뒤 새 비밀번호로 변경할 수 있습니다. 변경이 완료되면 사용자 인증 버전을 증가시키고 모든 Refresh Token을 삭제하여 기존 기기의 Access Token과 세션을 즉시 무효화합니다.

커뮤니티에는 아이디를 공개하지 않으며 닉네임만 표시합니다. 비밀번호 원문은 저장하지 않습니다.

로그인한 사용자는 자신의 냉장고 데이터, AI 레시피, 커뮤니티 게시물과 북마크에만 소유자 권한을 가집니다.

My Page의 `회원 탈퇴`는 `정말로 탈퇴하시겠습니까?` 확인 후 실행합니다. 탈퇴하면 사용자 계정, 인증 세션, 냉장고, 스캔, 댓글, 북마크와 사용 기록을 삭제합니다. 사용자가 공유한 레시피 게시물은 커뮤니티 콘텐츠 보존을 위해 남겨두고 작성자를 `익명`으로 표시합니다.

## 3. 하단 탭

하단 탭은 다음 세 개로 구성합니다.

1. 냉장고
2. AI 레시피 생성
3. 커뮤니티

기존 `MyRecipe` 탭은 제거합니다.

## 4. AI 레시피 생성과 공유

AI가 생성한 레시피는 생성 직후 자동으로 커뮤니티에 공개하지 않습니다.

사용자가 생성 결과에서 `커뮤니티에 공유`를 선택하고 확인해야 공개 게시물로 등록됩니다.

공유 확인 단계에는 다음 정보를 표시합니다.

- 작성자 닉네임
- 레시피 이름
- 공개될 재료명

공유된 레시피는 커뮤니티 목록과 `나의 요리책 > 내 레시피`에 표시합니다.

동일한 사용자가 내용이 같은 레시피를 반복해서 공유할 수 없게 합니다.

## 5. 커뮤니티 목록

커뮤니티 목록의 각 레시피 카드에는 다음 정보만 우선 표시합니다.

- 작성자 닉네임
- 레시피 이름
- 주요 재료명
- 북마크 표시
- 공개 북마크 횟수

카드를 누르면 레시피 상세 화면으로 이동합니다.

목록의 기본 정렬은 북마크 수, 댓글 수, 최신 공유 시각 순의 인기순으로 하며 사용자가 최신순으로 전환할 수 있습니다.

## 6. 레시피 상세

레시피 상세 화면에는 AI가 생성한 전체 레시피 정보를 표시합니다.

- 작성자 닉네임
- 레시피 이름과 설명
- 인원
- 조리 시간
- 사용 재료와 양
- 추가로 필요한 재료
- 재료 손질 방법
- 조리 순서
- 안전 주의사항
- 북마크 여부와 공개 북마크 횟수

다른 사용자의 레시피에는 북마크 등록·해제 기능을 제공합니다.

자신의 레시피에는 북마크 기능을 제공하지 않습니다.

## 7. 북마크 규칙

- 로그인한 사용자만 북마크할 수 있습니다.
- 한 사용자는 같은 레시피를 한 번만 북마크할 수 있습니다.
- 사용자는 자신의 레시피를 북마크할 수 없습니다.
- 북마크 횟수는 모든 사용자에게 공개합니다.
- 북마크 등록 시 공개 횟수가 1 증가합니다.
- 북마크 해제 시 공개 횟수가 1 감소합니다.
- 북마크 횟수는 실제 북마크 관계 수를 기준으로 계산합니다.
- 삭제되거나 존재하지 않는 레시피에는 북마크할 수 없습니다.

## 8. 검색

커뮤니티 화면 맨 위에 검색창을 배치합니다.

검색 대상은 다음 두 항목입니다.

- 레시피 이름
- 재료명

검색어가 없으면 최신 레시피 목록을 표시합니다. 검색 결과가 없으면 별도의 빈 상태 안내를 표시합니다.

검색은 Backend에서 처리하며 Frontend가 전체 게시물을 내려받아 직접 검색하지 않습니다.

## 9. 나의 요리책

커뮤니티 화면 우측 상단에 `나의 요리책` 진입 버튼을 배치합니다.

나의 요리책은 다음 두 영역으로 구분합니다.

1. 내 레시피
2. 북마크한 레시피

나의 요리책 상단에는 레시피 이름과 재료명으로 검색할 수 있는 검색창을 배치합니다. 검색은 Backend에서 처리하며 동일한 검색어를 `내 레시피`와 `북마크한 레시피` 양쪽에 적용합니다.

로그인 후 공통 상단 좌측에는 뒤로가기 버튼을 표시합니다. 탭, 커뮤니티, 나의 요리책 이동 이력을 역순으로 복원하며 레시피 상세가 열려 있으면 상세 화면을 먼저 닫습니다. Android 시스템 뒤로가기도 같은 규칙을 사용합니다.

### 9.1 내 레시피

`내 레시피`에는 사용자가 AI로 생성한 뒤 커뮤니티에 공유한 레시피를 표시합니다.

각 항목에는 다음 정보를 표시합니다.

- 레시피 이름
- 재료명
- 공개 북마크 횟수
- 삭제 버튼

삭제 버튼을 누르면 즉시 삭제하지 않고 다음 내용을 포함한 확인 단계를 표시합니다.

- 커뮤니티에서 레시피가 삭제된다는 안내
- 다른 사용자의 연결된 북마크도 함께 사라진다는 안내
- 취소 버튼
- 최종 삭제 버튼

작성자 본인만 자신의 레시피를 삭제할 수 있습니다.

### 9.2 북마크한 레시피

`북마크한 레시피`에는 다른 사용자가 공유한 레시피 중 현재 사용자가 북마크한 항목을 표시합니다.

각 항목에는 다음 정보를 표시합니다.

- 작성자 닉네임
- 레시피 이름
- 재료명
- 공개 북마크 횟수
- 북마크 해제 버튼

북마크 해제는 게시물 삭제가 아니며 현재 사용자의 북마크 관계만 제거합니다.

## 10. 삭제와 데이터 정합성

레시피 게시물을 삭제할 때 게시물과 연결된 모든 북마크를 함께 삭제합니다.

게시물과 북마크 삭제는 하나의 데이터베이스 Transaction 또는 관계형 cascade 정책으로 원자적으로 처리합니다.

Frontend가 작성자 ID를 신뢰하여 권한을 결정하지 않습니다. Backend가 로그인 사용자와 게시물 작성자를 비교하여 삭제 권한을 확인합니다.

다른 사용자의 게시물 삭제 요청에는 `403 Forbidden`을 반환합니다.

회원 탈퇴 시 공유 레시피의 작성자 외래키는 `NULL`로 전환하고 게시물은 유지합니다. 탈퇴 후 해당 게시물은 더 이상 `내 레시피`에 속하지 않으며 작성자 닉네임은 `익명`으로 반환합니다.

## 11. 용어

| 용어 | 의미 |
|---|---|
| AI 레시피 | 냉장고 재료를 바탕으로 AI가 생성한 결과 |
| 공유 | AI 레시피를 커뮤니티 게시물로 공개하는 작업 |
| 내 레시피 | 현재 사용자가 생성하고 커뮤니티에 공유한 레시피 |
| 북마크한 레시피 | 다른 사용자의 공개 레시피 중 현재 사용자가 저장한 항목 |
| 나의 요리책 | 내 레시피와 북마크한 레시피를 구분해 보는 개인 화면 |

## 13. 후속 구현 순서

사용자·인증 Backend와 Frontend, 냉장고 사용자 분리, 커뮤니티 모델, 기존 `SavedRecipe` 보존 migration, AI 레시피 공유 확인, 북마크, 커뮤니티 목록·상세·검색, `나의 요리책` 조회·삭제·북마크 해제를 완료했습니다. AI 레시피는 생성 직후 자동 공개되지 않으며 작성자 닉네임, 레시피 이름, 공개 재료를 확인하고 최종 공유해야 등록됩니다.

Android 실기기에서 커뮤니티 목록과 상세 진입·복귀, `나의 요리책` 진입, `내 레시피`와 `북마크한 레시피` 전환, 목록 개수와 빈 상태 표시를 확인했습니다. 공유 확정·삭제·북마크 해제처럼 데이터를 변경하는 동작은 자동 실기기 점검에서 실행하지 않고 DB 통합 테스트로 검증합니다.

커뮤니티 조회 API:

- `GET /v1/recipe-posts?q={검색어}&sort=popular|latest`
- `GET /v1/recipe-posts/:id`
- `GET /v1/recipe-posts/mine?q={검색어}`
- `GET /v1/recipe-posts/bookmarked?q={검색어}`

목록은 인기순 또는 최신순으로 최대 50개를 반환합니다. 검색어는 레시피 이름 또는 재료명의 부분 일치로 처리하며 영문 대소문자를 구분하지 않습니다. 목록 응답에는 전체 레시피 본문을 포함하지 않고, 상세 응답에서 전체 레시피를 제공합니다. 두 응답 모두 현재 사용자의 북마크 여부와 본인 작성 여부를 포함합니다.

AI 레시피 공유 API:

- `POST /v1/recipe-posts`

로그인한 사용자만 호출할 수 있으며 작성자는 Access Token에서 결정합니다. 동일한 사용자가 내용이 같은 레시피를 다시 공유하면 새 게시물을 만들지 않고 기존 게시물을 반환합니다.

북마크 API:

- `POST /v1/recipe-posts/:id/bookmark`
- `DELETE /v1/recipe-posts/:id/bookmark`

본인 게시물은 북마크할 수 없습니다. 등록과 해제는 반복 요청에도 결과가 달라지지 않게 처리하며 공개 북마크 횟수는 실제 북마크 관계 수를 기준으로 계산합니다.

현재 구현된 인증 API는 다음과 같습니다.

- `POST /v1/auth/register`
- `POST /v1/auth/login`
- `POST /v1/auth/refresh`
- `POST /v1/auth/logout`
- `GET /v1/auth/me`
- `DELETE /v1/users/me`

Access Token은 15분 동안 유효한 Bearer JWT이며 Refresh Token은 30일 동안 유효합니다. Refresh Token 원문은 DB에 저장하지 않고 SHA-256 해시만 저장하며 갱신할 때마다 회전합니다.

다음 API는 Bearer Access Token이 필수이며 로그인 사용자의 데이터만 처리합니다.

- `POST /v1/expiration-scans`
- `GET /v1/expiration-items`
- `POST /v1/expiration-items`
- `PATCH /v1/expiration-items/:id`
- `DELETE /v1/expiration-items/:id`
- `POST /v1/recipe-suggestions`

인증 도입 전에 저장된 냉장고 항목과 스캔은 migration 시점의 기존 사용자에게 귀속하여 보존합니다. 다른 사용자의 식재료 ID로 조회, 수정, 삭제 또는 AI 레시피 생성을 요청하면 해당 리소스의 존재를 노출하지 않고 `404 Not Found`를 반환합니다.
